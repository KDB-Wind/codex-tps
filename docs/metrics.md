# 指标口径与结果解读

## 指标定义

| 指标 | 计算口径 | 使用范围 |
|---|---|---|
| 本轮生成 TPS 估计 | 各普通响应 `(output_tokens - 1)` 之和 / 对应客户端输出窗口秒数之和 | 全部普通响应计时有效时显示；包含推理及可确认计时的工具参数，排除已识别压缩，不是服务端纯解码测量 |
| 本轮已测 | 仅已验证普通响应的 token 间隔 / 对应输出窗口秒数 | 有可信部分计时但覆盖不完整时显示，必须附普通输出 token 覆盖率；不代表整轮速度 |
| 近期生成 TPS 估计 | 同记录设置最近最多 5 个有效轮次的总 token 间隔 / 总生成窗口秒数 | 自动行标注实际有效轮数，单个样本不代表稳定趋势 |
| 会话生成 TPS 估计 | 同记录设置的全部已保存有效轮次的总 token 间隔 / 总生成窗口秒数 | 自动行标注纳入的有效轮数，历史记录受保留上限约束 |
| 非推理整轮吞吐 | `(output_tokens - reasoning_output_tokens) / 整轮秒数` | 仅在详情中显示，包含首字等待、工具执行与客户端开销 |
| 总输出整轮吞吐 | `output_tokens / 整轮秒数` | 仅在详情中显示 |
| TTFT | 完成事件的 `time_to_first_token_ms` | 后台回填后查询，默认行不附带其他轮次的 TTFT |

默认行包含本轮、近期、会话三个明确标注的生成 TPS 估计，以及排除已识别压缩后的输出数。完整计时显示“本轮”，部分计时显示“本轮已测”与覆盖率，没有可信窗口时显示不可测原因。历史没有有效样本时显示“暂无有效样本”，不显示 0 或借用另一项。`scripts/status.mjs --json` 保留含压缩的总用量、范围拆分、覆盖率、全部排除理由、整轮耗时及 TTFT。
`status.mjs --verbose` 保留旧版详细整轮吞吐行与可选 OTel 参考。

`status.mjs --details` 输出当前结果、响应/输出 token 的计时覆盖率、完整和部分历史，以及全部排除原因；
`--recent` 单独显示当前选择的近期比较。完整历史使用 `recentGeneration` / `sessionGeneration`，
部分历史使用 `recentPartialGeneration` / `sessionPartialGeneration`。两类不混算。
本轮部分可测时，主行显示“近期已测 / 会话已测”；本轮完整或不可测时优先显示“近期完整 / 会话完整”，
完整历史没有样本才显示明确标注的部分历史。
近期取对应类型最近最多 5 个有效轮次，会话取全部已保存的有效轮次；记录中的模型、provider、推理强度必须一致，
按 token 间隔总数除以生成时间总数加权。未知设置明确标注未知，不把历史均值替代当前轮。

`sessionGeneration` 使用相同过滤和加权规则，取全部已保存的同设置有效轮次；`sampleLimit=null`，
`historyScope=retained-session-records`。现有保留上限为每会话 200 个状态文件 / 2 MiB，超过后裁剪旧文件，
所以会话值按当前保留的有效记录计算。近期和会话都匹配当前轮记录的模型、provider、推理强度，切换设置后不混算。

证据版本为 4，公式继续使用各响应 N−1 个 token 间隔。完整版本 3 历史因公式相同继续可用，旧版保存的部分证据不自动升级。
`latest.generation.available` / `coverageComplete` / `tps` 保持完整计时语义；部分计时为 false / false / null。
`sampleAvailable` / `measuredTps` 表示经过校验的已测样本；`coverageType` 为 `complete`、`partial` 或 `unavailable`。
部分覆盖率 `measuredOutputTokenFraction` = 已测普通输出 token / 全部普通输出 token，排除压缩。
工具先出现、无效计时、无法匹配工具执行或某响应的推理/正文计时缺失，只排除该响应，其他有效响应仍可作为部分样本。
解析缺口、冲突用量、去重不可靠、未归类响应、跨响应窗口重叠、未配齐的输出或中断会使所有生成样本不可用。
匹配窗口覆盖一个响应中从可靠输出起点至最后生成完成的整个时间跨度，重叠输出项只计算一次，保留期间的间隔；工具执行开始后才写入的调用记录不能冒充参数生成结束点。
短输出在默认行标注，不按固定速度阈值删除数据。单 token 没有 token 间隔，保持不可测。部分样本可能偏向容易计时的响应，不能冒充整轮速度或无偏模型基准。

当前计时方法先收集整轮证据，再判定每个响应。模型输出项按 ID 回补迟到的计时；工具执行优先按调用 ID
关联，外层调用与内部项 ID 不同时，使用具有相同 `call_id` 的调用/返回边界核验唯一归属。
支持 `FileChange` 的已完成执行计时。后台 `CommandExecution` 必须已完成，其启动时间处于唯一调用/返回边界内，
且原调用先返回、进程后完成，才能认定为脱离原调用继续运行；后续输出不被这个后台区间排除。
无法证明归属或仍在阻塞的执行与输出重叠，继续排除受影响响应。返回身份缺失或时间冲突仍不猜测。推理用量明确为 0，
且对应推理项没有可见摘要/正文时，空推理占位项不参与正文计时；加密内容不作 token 估计。
完成事件落盘后，后台再读取一次有上限的日志以更新保存的生成证据；已显示的 Hook 行不会被改写。

历史 JSON 提供 `coverageType`、有效/排除轮数、token 覆盖率、样本捕获时间和 `latestTurnIncluded`。
`turnsSinceLastSample` 是最新样本之后的同设置轮数，`sampleAgeMs` 相对查询时刻计算。
至少 5 个后续同设置轮次，或样本已超过一小时时，`stale=true`，主行标注“旧样本”；这不是新的测速结果。

`token_usage_record.usage` 按响应 ID 去重，旧 `token_count` 镜像不重复相加，未覆盖的旧响应只补用量。相同 token 数的不同响应保持独立，冲突的显式记录使当前轮指标不可用。
旧快照在新 turn 中重播且累计输出与上一轮末尾相同时，不作为新响应计数；缺少上一轮基线时不凭相同 token 数猜测去重。
总用量包含已计入的所有响应；`responseMetrics.scopes` 单列普通、压缩和未归类用量。压缩关联依赖相邻完成记录，无法确认的范围保持未归类。

`output_tokens` 已包含 reasoning，不再加一次。非推理输出也可能包含工具参数，不等于只对最终正文做分词。
`modelGroups` 按本轮观察到的模型、provider、reasoning effort 分组，并以 token 与时长加权；未知设置保持独立。旧 `session` 与 `metric` 字段保留兼容，可能混合不同模型，不作为同模型速度比较。

## 输出示例与解读

以下数字用于展示格式，不代表模型速度基准。

```text
⚡ 生成 TPS 估计 · 本轮 ≈32.8 tok/s · 近期完整 ≈35.2 tok/s（5轮） · 会话完整 ≈34.6 tok/s（12轮） · 输出 2.5k tok
⚡ 生成 TPS 估计 · 本轮 ≈61.6 tok/s（短输出） · 近期完整 ≈35.9 tok/s（5轮） · 会话完整 ≈34.8 tok/s（13轮） · 输出 87 tok
⚡ 生成 TPS 估计 · 本轮 暂不可测 · 近期完整 暂无有效样本 · 会话完整 暂无有效样本 · 输出 200 tok
```

主行始终采用 token 间隔 / 输出窗口口径；完整与部分覆盖明确区分，不使用整轮吞吐替代缺失值。短输出标注只提示样本波动，不能视为稳定模型速度。
JSON 的 `displayMetric` 表示当前紧凑显示选择，旧 `metric` 始终保留整轮吞吐语义。
整轮生成速率需要每个普通响应均有可靠匹配；部分速率仅描述已验证响应。两者都不能通过整轮减去工具耗时或减去一次 TTFT 推算。

不同模型、推理强度、缓存、输出长度、服务档位和工具负载都会改变结果。查询 `modelGroups` 中相同条件的样本，再比较带覆盖率的加权均值；单个短回复不能作为模型速度结论。
未回填 TTFT 保持缺失，不显示为零。可选 OTel 的 TBT 参考只在详情出现，始终保留未归轮说明。
