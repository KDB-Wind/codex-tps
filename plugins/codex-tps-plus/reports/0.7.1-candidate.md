# 0.7.1：固定生成口径与本地统计

日期：2026-10-02。此版修正 0.7.0 主行在生成估计与整轮吞吐之间切换造成的混淆。

## 默认行为

```text
⚡ 生成 TPS 估计 ≈49.0 tok/s · 输出 653 tok
⚡ 生成 TPS 估计 ≈61.6 tok/s · 输出 87 tok（短输出）
⚡ 生成 TPS 暂不可测 · 输出 2.2k tok
```

主行只有一种速率口径，不再拿整轮吞吐替代计时缺失。整轮吞吐和 TTFT 留在本地 `status.mjs --json` / `--verbose` 详情。

每个普通模型响应分别取客户端输出窗口，公式为：

```text
sum(output_tokens - 1) / sum(output_window_seconds)
```

首个到末个输出之间对应 N−1 个间隔，多个响应各减去一个首 token。工具执行、请求间等待、首字等待与已识别压缩均不进入生成窗口。推理 token 与非推理输出需要对应的输出项计时；缺少 reasoning 用量拆分、缺少对应计时、单 token、工具先出现、窗口冲突等情况保持不可测。

计时来自持久化的客户端输出项与可确认范围的输出记录，而非服务端逐 token 解码追踪。输出项开始/结束与真正 token 时刻仍可能存在差异，隐藏推理的完整时间覆盖也不能只靠字段名称保证；因此保留“估计”，不承诺精确服务端 TPS。暂不加入滚动平滑或受控生成测试，以免掩盖测量限制或产生额外模型请求。

状态 schema 升为 8，继续读 v1–v7；新生成公式标记 `measurementVersion: 2`。旧生成估计只保留兼容详情，不自动换算为新 TPS，模型分组生成平均也不会混合旧公式。

## 零额外模型请求

自动流程只有同步 collector 和异步 backfill 本地脚本。它们读取已有本地日志与数字状态，不创建模型请求，不启动新 turn，不向模型追加统计上下文。Hook 输出只为 UI `systemMessage`，背景回填输出 `{}`。

`$tps` / `$tps-doctor` 属于让 AI 执行命令并解释结果的 Skill，用户调用后那次 AI 对话仍会消耗 token。因此本版移除 Skill 注册与隐式 `skills/` 目录，同时移除默认 prompt 建议，改为[本地命令](../docs/local-commands.md)。本地查询本身不调用模型；用户另外请 AI 解释查询结果的对话仍遵循正常计费。

新增回归测试在禁止网络模块、fetch/WebSocket 和子进程导入的环境中运行生产 Hook，验证统计和完成回填实际成功，以及不存在模型驱动的查询 Skill。此验证针对生产 Hook，不把显式 OTel 实验接收器纳入自动路径。

## 验证范围

使用合成输入和本地已有日志；不发送模型请求。检查单位测试、版本/包结构、CLI 0.153.4/0.159.2/0.160.0 的隔离安装升级，保留历史状态和稳定运行时恢复。

本机结果：121 项测试通过；三个 CLI 版本各通过 10 项隔离安装/升级冒烟，模型请求数均为 0；候选发布结构与 `git diff --check` 通过。用户授权的本机安装目标为 `codex-tps-plus@personal` 0.7.1，CLI 本体保持 0.159.2。

尚未完成受控流式计时的误差对照，也未执行新版远端跨平台 CI。此次改动解决指标混用与零额外请求约束，不把日志估计升级为精确测速承诺。
