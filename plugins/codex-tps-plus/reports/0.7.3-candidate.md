# 0.7.3：修复迟到事件关联与改善比较

日期：2026-10-02。修复用户提供的“生成 TPS 暂不可测 · 输出 5.4k tok”对应记录，而不放宽完整计时覆盖要求。

## 计时内核

旧解析在显式 usage 到达时立即判定窗口并清空 pending；随后记录的工具完成及起始时间无法回补，甚至污染下一响应。新版先收集本轮证据，再统一判定窗口。

模型原始项与 native 计时使用同一 ID。工具优先使用明确 ID；外层调用 ID 与内部工具 ID 不同的包装调用，使用原始调用和返回同一 call_id 构成的边界核验内部项归属。仅当归属唯一、时间有效、参数完成早于执行且生成区间不与任何已观察工具执行重叠时通过。并行的内部工具同属一个包装调用可以关联，跨响应包装边界歧义保持不可测。未映射的执行类型、工具先出现或遗漏起点仍不能产生整轮 TPS。

明确 reasoning_output_tokens=0 且推理 native/raw 项无可见内容时，空推理项不贡献 token 或生成时间。加密内容保持不透明，不据其长度推断 token。推理用量为正或未知时仍要求计时证据。

完成后台在 task_complete 落盘后做一次有界重读，更新保存的同用量生成证据及响应计数，保持捕获顺序和完成计时。自动 Hook 仍执行固定本地脚本，无模型或统计网络请求；已打印行不改写。

## 显示及比较

不可测主行给出简短原因。--details 提供覆盖率和近期加权值；--recent 单独查询近期值。JSON 的 recentGeneration 选本会话最近 5 个相同记录模型/provider/effort 的完整计时轮次，使用总 token 间隔 / 总生成时长加权，明确样本数、排除数、捕获时间、短输出样本数和当前轮是否入选。未知设置保持未知。可选 tps / tps-doctor 同步说明这些字段。

计时方法升级为 measurementVersion=3；旧证据保留可读详情，不自动转换或混入新比较。公式仍是 sum(output_tokens - 1) / sum(client output-window seconds)，客户端窗口包含窗口内的间隔，不能承诺服务端逐 token 解码精度。
